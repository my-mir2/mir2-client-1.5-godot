# 1.5 客户端 CM 协议号逆向清单 (radare2 实证)

> 来源：`reference/MIR_final_v3_p - Copy.exe`（官方 1.5 客户端）
> 方法：定位消息构造函数 `fcn.00458d3c`（52 处调用）与通用发送函数 `fcn.00464b18`（6 处调用），
> 提取每个调用点的协议号立即数。**这是从官方二进制直接提取的 CM 协议号全集**。

## 提取方法
1. `fcn.00458d3c` = TChrMsg 消息构造（协议号在 ax，offset4 写入消息）
2. `fcn.00464b18` = 通用发送包装（协议号经 edx）
3. 每个调用点前 `mov ax/edx, imm` 即协议号

1000 1001 1002 1003 1004 1006 1007 1008 1009 1010 1011 1012 1013 1014 1015 1016 1018 1019
1020 1021 1022 1023 1024 1025 1026 1027 1028 1029 1030 1031 1032 1033 1034 1035 1036 1037

## 【2026-09-04 IDA 定案】登录/账号族号段（登录场景审计, 详见 docs/场景审计报告/login-scene.md）

| CM | 语义 | payload | 证据（IDA MCP） |
|---|---|---|---|
| **2001** | 登录 (CM_IDPASSWORD) | `account + '/' + password`（分隔符 0x2F @0x464C8C） | sub_464B94 → sub_458D3C(2001) |
| **2002** | 新建账号 (CM_ADDNEWUSER) | 148B TUserEntry + 101B 问答字段 | sub_464C90 → sub_458D3C(2002) |
| **2003** | 修改密码 | account/old/new | sub_464F64 → sub_458D3C(2003) |
| **2004** | 更新账号 | 同 2002 形制 | sub_464DAC → sub_458D3C(2004) |
| **104** | 选服 (CM_SELECTSERVER) | 无 payload | sub_464EC8 → sub_458D3C(104)（DSServer1Click 0x488028） |
| **102** | 删除角色 (CM_DELCHR) | — | sub_465234（xref sub_47EA80 选角场景） |

> 旧结论"2001-2004 = 行会/城堡扩展"**有误**——实为登录/账号族（登录场景全部发送函数实锤）。
> 旧推测"100=CM_IDPASSWORD"**有误**——登录=2001。

## 关键结论
1. **CM 最高号 = 3030**，无 3035（坐骑）→ 证实官方 1.5 无坐骑 ✅
2. **2001-2004** 存在（行会/城堡扩展消息）
3. 文档 CM 表**严重不完整**（55 个实际 vs 9 个记录）
4. `1005/1017/1042` 需要确认是否接收侧（SM 处理）

## 🔴 重大发现：Rust 消息数 vs 官方协议号
| 项 | 数量 | 差异 |
|---|---|---|
| Rust `messages.rs` Cm 变体 | **92** | |
| 官方 1.5 exe CM 协议号 | **55** | **Rust 多出 37 个** |

**含义**：Rust 的 Cm 消息设计**远超官方 1.5 协议**。可能原因：
- A. 多个 Rust 变体映射到同一官方协议号（语义细分）
- B. **自造消息**（官方没有对应协议号）→ 需按 1.5 边界裁决
- C. 协议号不同的同名功能（新旧协议并存）

> 这是「功能是否超 1.5」的核心证据。下一步：将 92 个 Rust Cm 逐一映射到 55 个官方协议号，
> 无法映射的即为潜在超 1.5 消息。

## 复现命令
```bash
r2 -q -c "aaa; axt fcn.00458d3c" "MIR_final_v3_p - Copy.exe"   # 52 发送点
r2 -q -c "aaa; axt fcn.00464b18" "MIR_final_v3_p - Copy.exe"   # 6 发送点
# 每个调用点 pd -6 看 mov ax/edx, imm
```
